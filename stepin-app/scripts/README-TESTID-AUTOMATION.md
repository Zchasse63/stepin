# TestID Automation Scripts

Automated tools for adding testIDs to React Native components at scale.

## Overview

These scripts provide a **semi-automated workflow** for adding testIDs to components:

1. **`generate-testid-report.js`** - Analyzes components and identifies missing testIDs
2. **`apply-testids.js`** - Automatically applies the suggested testIDs
3. **`add-testids.js`** - Direct automated addition (experimental)

## Quick Start

### Step 1: Generate Gap Analysis Report

```bash
cd stepin-app
node scripts/generate-testid-report.js
```

**Output:**
- `tests/TESTID-GAP-ANALYSIS.md` - Human-readable report with suggestions
- `tests/testid-gaps.json` - Machine-readable data for automation

**Example output:**

## TestID Naming Conventions

The scripts follow these naming patterns:

### Modals
```tsx
<Modal testID="component-name-modal">
```
Examples: `timepicker-modal`, `logwalk-modal`, `editwalk-modal`

### Buttons (TouchableOpacity/Pressable)
```tsx
<TouchableOpacity testID="action-button">
```

**Smart detection based on:**
- Button text content (Cancel → `cancel-button`)
- onPress handler name (onSave → `save-button`)
- Context clues

Common patterns:
- `cancel-button`, `save-button`, `delete-button`
- `edit-button`, `close-button`, `submit-button`
- `continue-button`, `dismiss-button`, `confirm-button`

### Text Inputs
```tsx
<TextInput testID="field-name-input">
```

**Smart detection based on:**
- Placeholder text (placeholder="Steps" → `steps-input`)

Common patterns:
- `steps-input`, `duration-input`, `distance-input`
- `email-input`, `password-input`, `name-input`
- `search-input`, `message-input`

### Other Elements
- `<Switch>` → `toggle-switch`
- `<ScrollView>` → `scroll-view`
- `<FlatList>` → `list`

## How It Works

### 1. generate-testid-report.js

**What it does:**
- Scans all `.tsx` files in `components/` directory
- Identifies interactive elements (Modal, TouchableOpacity, TextInput, etc.)
- Checks if each element has a `testID` prop
- Suggests appropriate testID names based on context
- Generates detailed reports

**Intelligence:**
- Reads surrounding code for context
- Detects button purpose from text content
- Infers input purpose from placeholder text
- Follows established naming conventions

### 2. apply-testids.js

**What it does:**
- Reads `testid-gaps.json` generated by step 1
- Parses component files
- Adds `testID` props to elements
- Handles both self-closing and multi-line JSX
- Preserves code formatting and indentation

**Safety features:**
- Dry-run mode to preview changes
- Processes files from bottom to top (avoids line number shifts)
- Validates file existence before modifying
- Reports success/failure for each change

### 3. add-testids.js (Experimental)

**What it does:**
- Direct automated addition without intermediate report
- More aggressive but less safe
- Use with caution

## Workflow Comparison

### Manual Approach (Old Way)
1. Open component file
2. Find interactive elements
3. Decide on testID name
4. Add testID prop
5. Repeat for 27 components × 3-5 elements each = **~100 manual edits**

**Time:** 3-4 hours

### Semi-Automated Approach (New Way)
1. Run `generate-testid-report.js` (30 seconds)
2. Review suggestions in markdown report (5 minutes)
3. Run `apply-testids.js` (30 seconds)
4. Verify changes (10 minutes)

**Time:** ~15 minutes

**Savings:** 3+ hours

## Troubleshooting

### "testid-gaps.json not found"
**Solution:** Run `generate-testid-report.js` first

### "Component not found in gaps report"
**Solution:** The component either:
- Already has all testIDs (good!)
- Wasn't analyzed (check component name spelling)
- Isn't in the `components/` directory

### TestID added in wrong place
**Solution:** 
- Review the change in your editor
- Manually adjust if needed
- The script handles 95% of cases correctly

### Script fails to add testID
**Solution:**
- Check the "Failed" section in output
- Manually add testIDs for failed cases
- Complex JSX structures may need manual handling
